## UI and motion

CTU branding is implemented locally with the official full logo and observed burgundy/navy/cyan palette; see `../design/CTU_Brand_Reference.md`. Keep contrast, hierarchy and readable content ahead of decoration. The sidebar needs independent scrolling at short desktop heights; this is included with the brand update.

Existing motion is sufficient: 100 ms control feedback, 140 ms fade, 180 ms dialog/content and 220 ms drawer. Onboarding uses a short 180 ms step transition with heading focus moved to the new step. Reduced-motion rules disable animation and transitions. No animation package is needed. Animate state changes once; do not animate every row continuously or delay controls behind transitions. Preserve keyboard Escape, focus restoration, main-region focus and modal inertness.

True 200% zoom, an actual OS reduced-motion switch, screen-reader use, and touch-device testing remain acceptance work. Source support is not proof of those tests.

## Backend, privacy and security

The reviewed architecture has useful safeguards: verified email plus active approvedStudents membership, UID-scoped data, exact schemas, server timestamps, revision conflicts, transaction-based claims and owner-generation cleanup. Planner and import listeners reject cached/pending snapshots for confirmed state. Bridge messages check origin/path/window/request identity and parse data at the boundary. The extension has CTU host access and scripting, with no Firebase password/token handling. React text rendering and document URL constraints reduce injection exposure. No concrete cross-user bypass was found in this review; this is not penetration-test certification.

Keep imported portal context separate from institutional identity proof. The user explicitly selected account-based private saving without an extra identity confirmation. A portal capture therefore must not be used as trusted evidence of official marks, attendance or enrolment. Future facilitator membership and quiz answers require separate trusted permissions; private planner ownership cannot simply be broadened.

Current dependency audit: zero production advisories. Full audit reports seven development-tool entries, three high and four moderate, through firebase-tools and its transitive chain. Saved audit JSON is in the task outputs folder. Review a compatible CLI update separately; do not run a forced audit fix or blindly downgrade the toolchain.

No-billing boundary: [Firebase's current Storage requirements](https://firebase.google.com/docs/storage/faqs-storage-changes-announced-sept-2024) require Blaze for Cloud Storage. Future private file uploads therefore have an unresolved architecture/cost constraint. Do not enable billing or claim that Spark supports this feature. Existing CTU PDFs remain source links; timetable extraction is not yet class scheduling.
